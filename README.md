# Amallo

*A [41tunnels](https://41tunnels.com) project.*

**Use the AI models on your own computer from anywhere — securely.**

Amallo lets you keep [Ollama](https://ollama.com) and its language models running on your own Mac or PC, while still reaching them from your phone, another laptop, or a web app — wherever you happen to be. Your models and your conversations stay on your machine; Amallo simply opens a private, protected door to them over the internet.

It sits quietly in your menu bar (macOS) or system tray (Windows). One click puts your local AI online behind a personal access key, and only devices that have that key can connect — everyone else is turned away.

**Why use it**

- **Private by design** — everything runs on hardware you own; nothing is handed to a third-party AI provider.
- **Your models, on the go** — talk to them from a laptop, a phone, or a browser app like OpenCharUI.
- **No usage bills** — your own computer does the work, so there's nothing to pay per message.

## How it works

Under the hood, Amallo runs an authenticated reverse proxy in front of Ollama and pairs it with a self-hosted **relay** server over an outbound, end-to-end encrypted WebSocket connection. Once paired, a client (like OpenCharUI web) connects to the same relay and the two sides establish a real, independently-verified encrypted session — the relay only ever sees ciphertext; it forwards bytes it cannot read.

```
Web/phone ──wss── relay (forwards ciphertext only) ──wss── Amallo ──▶ proxy (127.0.0.1:11435) ──▶ Ollama (127.0.0.1:11434)
                                                              └ Bearer-token auth for direct/LAN clients
LAN (optional) ─────────────────────────────────────────────────┘
```

Pairing is a QR code (or a pasted code) generated by Amallo, encoding a relay URL, a pair ID, and a pre-shared key — scan it once from a client and it's connected for good, with no manual URL/CORS configuration on either side.

- **macOS** — lives in the menu bar (top).
- **Windows** — lives in the system tray (bottom).

## Features

- **Paired relay connection** — end-to-end encrypted (P-256 ECDH + AES-256-GCM), reconnects automatically, works from anywhere with no `OLLAMA_ORIGINS`/CORS setup on the client side.
- Reverse proxy with **bearer-token auth** — auto-generated 256-bit token, one click to copy or regenerate, for direct/LAN clients.
- Streams responses (NDJSON / SSE) so `ollama` and OpenAI-compatible clients work unchanged.
- Optional **LAN mode** — bind to `0.0.0.0` and use the same token on your local network directly, without going through the relay.
- Launch at login and connect to the relay automatically.
- Secrets (bearer token, pairing key) are stored in a `0600` file in Amallo's data dir — the same approach the AWS CLI and Docker use.

## Setup

1. Have [Ollama](https://ollama.com) running locally (default `127.0.0.1:11434`).
2. Launch Amallo → **Settings…** from the tray.
3. Scan the **pairing QR** from OpenCharUI web (Settings → Remote access), or copy the pairing code and paste it there instead.
4. That's it — Amallo connects to the relay automatically, and the client reconnects to it on its own from then on.

## Using it

For a browser-based client like OpenCharUI, pairing (above) is the whole setup — no manual URL or API key entry.

Direct/LAN clients (native Ollama or OpenAI-compatible tooling) still use the bearer token from the tray:

```bash
# native Ollama API
curl http://<lan-ip>:11435/api/tags -H "Authorization: Bearer <token>"

# OpenAI-compatible endpoint (use <token> as the API key)
curl http://<lan-ip>:11435/v1/chat/completions \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":"hi"}]}'
```

## Updates

Amallo checks GitHub for a newer release shortly after launch and every six
hours after that. When one exists it shows up in the tray menu and as a banner
in the settings window, whatever your settings say — the **Install updates
automatically** switch only decides whether installing needs a click.

An update never interrupts a live session. Installing restarts Amallo (on
Windows the installer force-exits it), so while a device is actually connected
the automatic path holds off and says so; it installs once that device
detaches. You can always override that from the settings window — it warns
first.

Updates are downloaded from this repo's releases and verified against a public
key built into the app; an unsigned or tampered bundle is refused and there is
no way to switch that off.

> **Upgrading from 1.1.0 or earlier:** those builds shipped before the updater
> existed, so they cannot update themselves. Download the current release once,
> by hand, and self-updating works from then on.

## Development

Prerequisites: [Rust](https://rustup.rs), Node 20+, and the [Tauri prerequisites](https://tauri.app/start/prerequisites/) for your OS.

```bash
npm install
npm run tauri dev      # run in development
npm run tauri build    # produce a release bundle for the current OS
```

Cross-platform releases are automated: pushing to `release/latest` runs [semantic-release](https://semantic-release.gitbook.io/) over the commit history (conventional commits — `feat:`/`fix:`/`BREAKING CHANGE`) to decide whether a release is warranted and what version it gets, then builds and publishes it — see [`.github/workflows/release.yml`](.github/workflows/release.yml). Tauri does not cross-compile, so Windows binaries are produced on a Windows runner and macOS ones (arm64 + Intel) on a macOS runner.

Release builds are signed for the updater, which needs two repo secrets —
`TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — holding
the keypair generated by `npm run tauri signer generate`. The matching public
key is committed in `src-tauri/tauri.conf.json`. **Keep the private key backed
up:** losing it means no installed copy can ever update itself again, because a
replacement public key only reaches users through a manual reinstall. A local
`npm run tauri build` without those variables set produces unsigned bundles and
no `latest.json`, which is fine for testing but is not a releasable artifact.

The release matrix deliberately runs one platform at a time (`max-parallel: 1`):
`tauri-action` assembles `latest.json` by merging into the copy already attached
to the release, so parallel legs would race and drop each other's entries.

## Notes & caveats

- Secrets live in `<app-data-dir>/secrets.json` with `0600` permissions (e.g. `~/Library/Application Support/io.github.opencharui.amallo/secrets.json` on macOS). It is **not encrypted at rest** — any process running as your user can read it, and it is not excluded from backups. This matches how the AWS CLI/Docker store their tokens. Delete the file to reset (a new bearer token and pairing key are generated on next launch).
- Regenerating the pairing code invalidates every device currently paired, including web, immediately.
- Amallo assumes Ollama's default loopback host. A custom `OLLAMA_HOST` upstream isn't configurable yet.

## 41tunnels

Amallo is one of three products under the [41tunnels](https://41tunnels.com) umbrella — tools for using your own AI models from anywhere, privately, without handing your models or your conversations to a third-party provider:

- **Amallo** (this repo) — the desktop agent that opens the door.
- **Relay** — the self-hosted server that splices connections without ever reading them.
- **OpenCharUI** — a browser roleplay chat app that pairs with Amallo to reach your own models.
